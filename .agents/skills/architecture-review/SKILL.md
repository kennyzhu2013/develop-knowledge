# Architecture Review

## Workflow

1. 执行 `understand-system`，覆盖方案涉及的所有域。
2. 列出与方案相关的现有 ADR，逐条判断：遵循 / 修改 / 推翻。
3. 按维度评审：

| 维度 | 关注点 |
| --- | --- |
| 业务 | 是否满足需求，是否引入业务语义变化 |
| 依赖 | 是否引入循环依赖、跨域同步调用 |
| 性能 | 延迟预算、吞吐、容量 |
| 可用性 | 单点、降级、对呼叫接续的影响 |
| 数据 | 一致性、留存、敏感数据、出境 |
| 运维 | 部署、监控、回滚 |
| 成本 | 资源、GPU、存储 |
| 演进 | 与后续规划是否冲突 |

4. 执行 `impact-analysis` 得到改动清单。
5. 给出 2~3 个备选方案及取舍。

## Output

结论 → 主要风险（按严重程度排序） → 备选方案对比表 → 建议新增的 ADR 草稿（使用 `99-agent/templates/adr.md`）
